## 친구 PC에서 원하는 범위

Windows에서 게임 4개를 실행한다. 각 게임 내부 화면은 800×600을 유지하고, 상하좌우 타일 대신 제목 표시줄이 보이도록 겹쳐 놓는다. 작업할 게임만 복원·활성화하고 실제 조작은 반드시 한 번에 한 창에만 보낸다. 사용자의 기존 2캐릭터 PC/설치본은 별도 유지한다. 새 폴더·별도 저장소 또는 독립 브랜치·독립 버전명·설정·로그로 관리하고 자동 병합/덮어쓰기하지 않는다. 새 저장소 이름은 친구가 정하며 아직 생성하지 않았다.

## 확정한 사냥 흐름

- 한국 시간 04:50 복자할매 창고 보관 → 주모 구매·상점 닫기. 보급 완료 후 05:01부터 남은 기본 특수지역을 순서대로 진행하고, 다섯 곳 완료 후 한밭 → 설정 일반사냥터 이동 → AUTO 확인.
- 기본 순서: 영혼의 동굴 → 부패한 도성 → 행주산성 → 전리품 매립지 → 조선왕릉. 층은 프로필별 설정. 원본 기본값은 2/4/3/3층이며 조선왕릉만 왼쪽1층/오른쪽2층이다. 친구 네 캐릭터의 층/일반사냥터는 별도 확인해야 한다.
- 원본 일반사냥터는 왼쪽 월정사·대웅전 입구, 오른쪽 대한해협·왜구 함선1 내부. V76에서는 임의 목적지 선택 UI가 아니라 Profile 안에 기본 목적지가 정해져 있다.
- 원본 이벤트: 양쪽 16:00~17:00 버려진 동굴. 오른쪽은 수요일 외 20:00~22:00 가덕도왜성, 수요일은 19:00~23:00 저주받은 니조성. 네 캐릭터에 동일하게 복제한다고 가정하지 말고 각 참여 설정을 확인한다.
- 버려진 동굴·가덕도왜성은 단일 층이므로 지역 선택 → 입장 → 확인 → AUTO. 불필요한 1층 클릭을 하지 않는다. 니조성은 월드지역 탭의 맨 위 대상 카드와 설정 층을 확인한다.
- 이벤트 종료 후 게임이 원래 사냥터로 돌려보내면 AUTO만 확인한다. 초계/한밭으로 복귀한 것을 확인하면 미니맵 → 전체 → 설정 지역 → 정확한 사냥터 → 이동 → AUTO 확인. 초계의 지역 목록 07번을 목적지로 재사용하지 않는다.
- 기본 특수지역을 모두 소진한 뒤 모래시계/추가 이용권으로 한 지역에 2~6시간 등 가변 시간을 충전할 수 있다. 특정 지역이나 4시간으로 고정하지 않는다. 남은 시간 단위와 카드 상태를 확인해 입장한다. 기본시간 만료와 충전시간 있음은 함께 표시될 수 있다.
- 추가 충전 사냥 종료 후 한밭으로 나오면 다른 특수지역을 재검색하지 않고 바로 설정 일반사냥터/AUTO로 연결한다. 기본 다섯 곳 순회와 구분한다. 70분 관찰 제한은 제거됐다. 숫자 OCR로 정확한 잔여 시각을 읽는 기능은 현재 없다.

## 기존 GUI 조작 의미

2분할 자동화는 전체 예약 켜기/끄기이며 녹색은 켜짐이다. 수동 START는 보급부터 지금 전체 흐름, 상점창고는 보급만, 특수지역은 현재 남은 기본 지역 재검사, 일반사냥은 설정 목적지 이동이다. 조작 구간 종료는 해당 작업의 종료이며 전체 예약 정지가 아니다.
이벤트 체크만 해제하면 이벤트 예약만 중단하고 새벽 보급/기본 순회는 유지한다. 시간이 남은 특수지역에서 일반사냥 버튼만 눌러 강제 퇴장하는 기능으로 보아서는 안 된다.
GUI 최소화는 트레이, X는 종료. 게임 자체 최소화는 미구현/미검증이다. 주기적인 창 전환으로 PC 사용을 방해하지 않도록 관찰은 가능한 범위에서 수동 노출/수동적 확인하고 필요한 실제 작업만 전환한다.
지난 04:50을 소급 실행하지 않는다. 보급 실패 후 늦게 복구하면 각 프로필 START로 보급부터 재개한다. 보급 실패가 있는데 05:01 무조건 입장시키지 않는다.

## 실제 확인과 미검증을 구분

실게임 확인: 기본 특수지역 연속 진행, 일반사냥↔버려진 동굴, 오른쪽 가덕도왜성/니조성 입장·AUTO 및 복귀 사례, Telegram 시험 수신, V74 추가 충전 4시간 입장과 양쪽 종료 후 일반사냥/자동전투(오른쪽은 재확인 후 완료), V75 초계에서 자동화 시작 후 기존 사냥터 복구 성공.
V75에서 초계로 간 최초 원인은 확정하지 못했다. 17:00:43 왼쪽 초계 지도, 17:00:48 오른쪽 초계 필드, 일반사냥 이동 기록은17:02 이후 클릭 검증 취소였다. 게임이 무조건 그곳으로 보냈다고 단정하지 않는다.
V75 클릭 기록 추가 과정에서 방향키 함수에 nx/ny 호출이 잘못 들어가 다음 날 NPC 탐색이 중단됐다. V76은 이를 바로잡고 모든 OS 입력을 mock한 방향키4종/마우스down-up/기록 범위 검사를 통과했다. 오른쪽 전투 효과로 HUD=0인 보급 출발은 사냥터 이름 근거로 보완했다. 출석창은 정상 인식했으나 보급 실패로 이후 순회가 시작되지 않았던 상황이다. 이 대화에서는 V76 적용 후 실제 새벽 전체 보급 완료에 대한 추가 사용자 확인을 아직 받지 않았다.
4개 겹침 창·게임 최소화·EXE 배포는 미구현/미검증. 공유 대화/문서만으로 실시간 상태나 다른 PC 실행 결과가 연결되지는 않는다.

## 네 창으로 바꿀 때 우선 볼 소스

- chosun_gui.py: Profile.right와 두 프로필/목적지 기본값. 4개 복제만으로 완료되지 않는다.
- floor_settings.py: JSON 키가 left/right 두 개다. char1~char4 같은 안정된 프로필 ID로 분리하고 호환/초기화를 정한다.
- event_schedule.py: events_for(right,day), profiles[0] 등 좌우 전제를 프로필별 이벤트 참여 설정으로 변경한다.
- dual_runner.py, work_coordinator.py: 관찰 및 한 번에 한 창 조작. 고정 두 인덱스/순서 가정을 제거하고 4개 독립 상태를 관리한다.
- window_link.py, focus_runner.py, focus_guard.py, runner_focus.py: 동일 제목 네 게임의 HWND 연결, 활성화/실제 위치 확인, 재접속 핸들 교체를 검증한다. 단순 x좌표 정렬로 캐릭터를 고정하지 않는다.
- passive_observer.py, observation_menu.py: 다른 창으로 가린 HUD를 잘못 읽지 않는다. 관찰 불가와 실제 정지를 구분한다. 필요 없는 주기적 전환을 새로 넣지 않는다.
- cycle_runner.py, special_runner.py, entry_runner.py, event_runner.py, recovery_runner.py, general_runner.py: 충전/기본 순회 구분, 중복 결제/재입장 방지, 실제 위치 기반 재개와 복귀.
- attendance.py, supply_runner.py 및 NPC/창고/구매 runner: 출석창 닫힘 확인과 보급 이어가기.
- single_instance.py: 고정 mutex 이름과 2캐릭터 제목 검사가 있어 별도 배포 정책을 검토한다. 두 컨트롤러가 같은 게임창에 동시에 입력하지 않게 한다.
- admin_launch.py: 관리자 실행과 Python 재실행 방식. EXE는 이 코드를 그대로 얼리기만 하지 말고 frozen 실행의 관리자 재실행·자산/설정 경로를 따로 검증한다.
- status_board.py, button_feedback.py, desktop_tray.py, telegram_*: 네 프로필 상태/버튼/알림 구분을 확장한다. Telegram은 화면 가림만으로 오류 알림을 보내면 안 된다.

## 네 창 전환판의 완료 조건

1. 친구 PC에서 캐릭터1~4와 네 HWND가 정확히 일대일 연결된다. 재시작한 한 게임만 다시 연결해도 다른 캐릭터가 바뀌지 않는다.
2. 제목 표시줄만 보이는 겹침에서 선택한 게임을 활성화한 뒤 내부800×600과 무가림을 확인하고 클릭한다. 다른 창 활성화/이동/사용자 마우스 개입 시 입력을 취소하거나 재확인한다.
3. 여러 예약이 동시에 와도 한 창의 입장·확인·AUTO 구간을 끝낸 뒤 다음 창으로 간다. 다른 캐릭터의 사냥/예약/완료 기록을 초기화하지 않는다.
4. 정상 시작, 일반사냥/한밭에서 이벤트 시간 중간 재개, 기본 특수지역 중 재개, 추가 충전 중 재개, 출석창, 예기치 않은 복귀, 연결 끊김/점검 후 수동 재접속을 각각 시험한다.
5. 중복 입장·중복 결제·잘못된 층·다른 창 입력·확인 전 완료 처리·가림 오탐 알림을 회귀 검사한다. mock/저장 화면 검사와 실제 게임 성공을 따로 기록한다.
6. 추가 충전 상태는 현재 메모리에 있어 GUI 재시작 후 의미가 사라질 수 있다. 4분할에서는 프로필별 재개 상태와 유효성 확인/저장 정책을 설계한다. V76의 모든 재시작 경로가 완벽하다고 가정하지 않는다.
7. 친구 PC의 Python 유무·OS/DPI·네 프로필의 층/일반 목적지/이벤트 참여·배포 저장소를 먼저 확인한다. V76 배포본은 Python 소스이며 EXE가 아니다.

## 전달하지 않을 개인 자료

원 사용자 PC의 Telegram 토큰/채팅 ID, hunting_floors.json, telegram_alerts.json, 실제 diagnostics, 전체 작업 메모를 그대로 공개하지 않는다. 친구는 자기 설정을 입력한다. 필요한 문제 화면/로그는 친구 PC에서 새로 수집해 민감 정보를 가려 공유한다.
